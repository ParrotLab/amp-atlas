# Editing basics

This is the everyday stuff: opening a document, making changes safely, and saving your
work. Once you've got this, everything else in AMP Atlas builds on it.

---

## First: you edit in a Draft, not the Live Version

Here's the one rule that shapes all editing in AMP Atlas: **you never edit the Live
Version directly.** The Live Version is official and shared, so it stays read-only. All
your changes happen in a **Draft** — your private, safe working copy.

So when you want to change something, the first step is to be in a Draft:

- If you're viewing the Live Version (the editor is read-only), **start a new Draft** —
  AMP Atlas will offer this when you go to make a change, or you can create one from the
  status bar.
- If you're already in a Draft, you're good to go.

The status bar always tells you which Draft you're in. If you ever see that the editor
won't let you type, it's almost always because you're looking at the Live Version — switch
to a Draft and you're off.

> Don't overthink this. A Draft is cheap and safe. Making one is the normal way to start
> any change, and nothing you do in it affects anyone until you publish.

---

## Opening and reading documents

Open any System from your dashboard, and you'll see its **file tree**. Click a document to
open it in the editor. Reading is always safe — click around, explore, follow your
curiosity. You can't break anything by looking.

---

## Writing and formatting

The editor is a clean, friendly writing space. You type normally, and formatting works the
way you'd expect from any modern editor — headings, **bold**, _italics_, lists, links,
quotes, and so on. There's nothing technical to learn and no special syntax you *have* to
memorize.

---

## Creating new documents and folders

To add something new, **right-click** in the file tree where you want it, and choose to
create a new document or folder. You'll be asked to name it, and it appears right where you
put it.

When you create certain things — like a new **Project** or **Playbook** — AMP Atlas can
start you from a **template**, so you get the right structure already laid out instead of a
blank page. See the [Templates guide](../04-reference/templates-guide.md) for what each one
gives you.

---

## Properties: the details attached to a document

Many documents carry a small set of **properties** — labeled details like a status, an
owner, or a date. You'll find these in the **properties** area when a document is open.

The most useful one is **status**, which tells everyone how finished a document is — for
example _draft_, _needs review_, or _approved_. Keeping status accurate helps your whole
team (and Claude) know what to trust. You don't have to fill in every property, but a
correct status goes a long way.

---

## Save vs. Publish — an important difference

These two sound similar but do very different things:

- **Save** keeps your progress **inside your Draft**. It makes sure nothing is lost. It
  does **not** make anything official, and nobody else sees it. Save early, save often.
- **Publish** takes an **approved** Draft and makes it the new **Live Version** — official,
  and visible to everyone. Publishing only happens *after a review*.

So your everyday rhythm is: work in a Draft, **Save** as you go, and only later — when the
work is ready and reviewed — **Publish**.

```
   work in a Draft  ──▶  Save (as often as you like)  ──▶  ...later...  ──▶  submit for review  ──▶  Publish
       (private)          (nothing official yet)                          (a teammate checks)     (now official)
```
