# Working on several projects at once

Real work is rarely one thing at a time. You might be refreshing the onboarding emails
*and* fixing a rubric *and* helping a teammate with a third thing — all in the same System.
AMP Atlas handles this with **multiple Drafts**: each separate piece of work gets its own
Draft, and they stay neatly out of each other's way.

---

## Each piece of work gets its own Draft

Think of a **Draft** as one workstream. Because a Draft is a private, self-contained copy,
you can have **several going at once** in the same System, each holding a different piece of
work. Changes in one Draft never leak into another. You publish each one separately, whenever
it's ready.

This is what lets a whole team work in the same System at the same time without stepping on
each other — everyone's changes live in their own Drafts until they're reviewed and
published.

> If you've ever been afraid to start a second task because you didn't want to mess up the
> first, this is the answer. Start a fresh Draft, and the two never touch.

---

## Creating and naming Drafts

When you start a new piece of work, create a **new Draft** and give it a clear name that
says what it's for — like "Onboarding email refresh" or "LAUNCH rubric fix." Good names
matter more than you'd think once you've got a few going; they're how you'll tell your
Drafts apart at a glance.

---

## Switching between your Drafts

You can move between your Drafts whenever you like — AMP Atlas simply shows you that Draft's
version of the System. The **status bar** always tells you **which Draft you're currently
in**, so you know which workstream you're touching before you make a change.

A good habit: glance at the status bar before you start editing, just to confirm you're in
the Draft you meant to be in.

---

## Where a new Draft starts from

Every new Draft starts from the **Live Version** — a clean, official starting point. This is
deliberate: it keeps each Draft simple and predictable, always built on top of the latest
approved work.

If you have edits you started on the Live Version by accident and want to move them somewhere
safe, AMP Atlas can **move those changes into a new Draft** for you. And if you already have a
piece of work in progress that lives outside AMP Atlas, the status bar's **Add existing
work** option lets you adopt it as a Draft.

> **What you can't do (yet):** start a Draft *on top of another in-progress Draft*. The New
> Draft window hints at this as an "Advanced" option, but it isn't available in this version —
> Drafts always begin from the Live Version. If you need to build on work that isn't published
> yet, the simplest path is to get that work reviewed and published first, then start fresh.

---

## Publishing them independently

Each Draft goes through its own [review](./submit-for-review.md) and gets **published on its
own schedule**. Finishing and publishing one Draft doesn't affect your others — they keep
sitting there, untouched, ready for you to come back to. You're never forced to finish
everything at once.
