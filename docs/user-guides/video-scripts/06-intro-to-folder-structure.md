# Video 6 — Intro to the AMP folder structure

**Format:** Loom screen-share of AMP Atlas
**Length:** ~4–5 min
**Goal:** Viewer can navigate a System's file tree, understands Reference vs. Work, and knows
where playbooks, projects, and sub-systems live (and how to add them).

---

## Before you record

- 💡 Open a **well-organized demo System** with real-looking content in each area (a couple of
  playbooks, some reference material, a project or two in Work).
- 💡 Have the **file tree** visible and expanded enough to show the shape.
- 💡 Know where the **+** buttons are for adding a playbook, project, and sub-system.

---

## The script

### 0. Cold open ⏱️ ~20s
**🖱️ On screen:** A System open with the file tree visible.
**🎙️ Say:** "Every System in AMP Atlas is organized the same way — and once you know the shape,
you'll always know where to find things. In this quick tour I'll walk you through a System's
folders so you feel at home in any of them."

### 1. The shape is a promise ⏱️ ~30s
**🖱️ On screen:** Slowly scroll the top level of the file tree.
**🎙️ Say:** "Here's the big idea: every System follows this same layout. It's like a
well-organized kitchen — plates in the cupboard, silverware in the drawer — you don't relearn
it each time. Same here. So let me point out the main areas."

### 2. The front door: Overview & context ⏱️ ~30s
**🖱️ On screen:** Point at / open the overview (README) and any long-form context docs.
**🎙️ Say:** "Up top there's the **overview** — a plain-language description of what this System
is and who looks after it. Alongside it, longer background docs — company context, how this
System connects to others. This is the front door."

### 3. Playbooks ⏱️ ~35s
**🖱️ On screen:** Expand the **Playbooks** area; open one playbook briefly.
**🎙️ Say:** "This is **Playbooks** — the repeatable processes this System can run, either by a
person or by Claude. Things like 'triage the support inbox' or 'grade a session.' Each one is a
step-by-step recipe. If you open one, you'll see it's got a clear structure — purpose, trigger,
the steps, and so on."

### 4. The big one: Reference vs. Work ⏱️ ~70s
**🖱️ On screen:**
- Point at **Reference**. Open a file or two.
- Then point at **Work → Projects**. Open a project folder.

**🎙️ Say:** "Okay, the single most important distinction in any System: **Reference** versus
**Work**. **Reference** is the canonical stuff — approved, trusted, the source of truth. Rubrics,
guides, finished templates. If it's in Reference, we treat it as true. **Work**, on the other
hand, is everything in-progress — active projects, drafts, things still being shaped. The reason
we keep them apart is simple: if a half-finished draft sat right next to the approved version,
nobody — human *or* Claude — would know which to trust. So the quick test whenever you're
deciding where something goes: is it finished and official? That's Reference. Still being worked
on? That's Work."

### 5. Inside a project ⏱️ ~35s
**🖱️ On screen:** Expand a project in Work → show its braindump, pitch, and other files.
**🎙️ Say:** "Inside Work, each **project** has its own little shape. It usually starts with a
**braindump** — raw thinking — and a **pitch** — the case for the work. Then you build up your
working files and the finished result alongside them as it grows."

### 6. Sub-systems ⏱️ ~20s
**🖱️ On screen:** Point at a sub-system area within Reference.
**🎙️ Say:** "For bigger Systems, you'll also see **sub-systems** — smaller areas a large System
is divided into, each with its own overview. It keeps a big System from becoming one giant pile."

### 7. Adding things (the + button) ⏱️ ~30s
**🖱️ On screen:** Hover/click the **+** on the relevant folders to show New playbook / New
project / New sub-system.
**🎙️ Say:** "And when you need to add something, the **+** on these folders starts you from the
right template — a new playbook here, a new project here, a new sub-system here. You don't have
to build the structure yourself; AMP Atlas lays out the right pieces for you."

### 8. What not to worry about ⏱️ ~20s
**🖱️ On screen:** Rest on the full tree.
**🎙️ Say:** "Last thing — relax and explore. Opening and reading files is always safe; you
can't break anything by looking. And the overall shape is already set up for you, so you can
just focus on your work."

### 9. Wrap ⏱️ ~15s
**🖱️ On screen:** The full System.
**🎙️ Say:** "That's the layout of a System: overview, playbooks, your trusted Reference, and
in-progress Work. Know those, and you'll find your way around any System. Thanks for watching!"

---

## If something goes wrong while recording

- **Your demo System has gaps** (empty Reference, no projects) — either populate it first, or
  narrate "in a fuller System you'd see…" rather than showing an empty folder.
- **The tree is cluttered** with technical files — collapse or scroll past them; keep the focus
  on the areas viewers actually use.
